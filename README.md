# go-csn1

Go decoders and byte-exact encoders for CSN.1 definitions extracted from current 3GPP specifications. [release-evidence.json](release-evidence.json) records the compiler commit, source archive and extracted-file hashes, typed corrections, source discrepancies, generated-file hashes and validation commands. It is regenerated by the compiler and checked for drift by `csn1c -check`.

## Installation

```bash
go get github.com/gomaja/go-csn1@main
```

No tagged releases are published. Depend on the `main` branch and update with
`go get github.com/gomaja/go-csn1@main`.

## Usage

```go
import "github.com/gomaja/go-csn1/ts36331/uecapability"

decoded, err := uecapability.DecodeGERANPS(container)
if err != nil {
    return err
}
encoded, err := uecapability.EncodeGERANPS(decoded.Value)
```

`BitsConsumed` and `Tail` are reported by every decoder. Values contain an explicit `Wire` record for received spare bits, padding, implicit zero spans, truncation, list stop records, the transmitted boundary and tail. Every encode uses the generated bit encoder; received bytes are not retained for replay. An unchanged decoded value re-encodes byte for byte. Plain `Encode<Type>` rejects edits that move a semantic boundary or conflict with retained wire state.

`Encode<Type>Canonical` is available for every generated type. It copies the typed value, discards received layout at every nested level, encodes the copy using the printed grammar, then decodes the result to check typed semantic equivalence within the definition's source-defined length. For TS 24.008 V20.1.0 §10.5.5.12a capabilities, zero-extension bits inferred by the receiver are omitted beyond the transmitted length. For TS 44.018 V19.0.0 §8.9 truncated concatenations, it chooses the shortest octet-aligned prefix that decodes equivalently. A mandatory minimum or fixed IE length is filled with the source's spare pattern (TS 44.018 §§10.5.2.17, 10.5.2.33; TS 24.007 V20.0.0 Annex B §B.1.2.2). Other definitions use their deterministic fresh grammar encoding. If no conforming equivalent encoding exists, canonical encoding returns an error. The caller's decoded value and its byte-exact plain re-encode remain intact.

Definitions without a standalone source maximum, including nested components whose extent comes from a containing message, require `Encode<Type>CanonicalAtLength(value, octets)` (or `Descriptor.CanonicalAtLength`). Their default canonical entry point returns a typed `runtime.ExtentError` instead of choosing an arbitrary bound. The caller supplies the value length imposed by its message or IE; the encoder rejects an extent outside a known source bound or one that cannot carry an equivalent typed value. `Descriptor.MaxOctets` is zero when the caller must supply the extent. SI7/SI8 use `Encode<Type>CanonicalWithContext` with the containing SI4 ACS bit and have a fixed 20-octet value. For an Enhanced Measurement Report, TS 44.018 V19.0.0 §9.1.55 defines semantic equivalence to include omitted redundant trailing no-report positions: a present pre-Rel-8 list is normalized to 96 positions, with absent positions represented by nil entries. TS 44.006 V19.0.0 §§5.1, 5.2, 8.8.3 limit its Bter SACCH encoding to 21 octets including the short L2 header. No other typed fields are normalized.

Every named rest-octet decoder returns `runtime.ErrEmptyValue` for zero input; use `errors.Is` to identify an absent value. This is distinct from a malformed nonempty value. The printed CSN.1 grammars require at least one bit even where the containing message permits an IE of zero octets. Newly constructed IA values use the octet-aligned `0x2B` L/H spare-padding pattern from TS 44.060 V19.0.0 §11 and TS 24.007 V20.0.0 Annex B §B.1.2.2. Decoded values preserve received padding.

`DecodeSI7RestOctets` and `DecodeSI8RestOctets` return `runtime.ErrContextRequired`, identifiable with `errors.Is` and carrying the specification, clause and printed name. TS 44.018 V19.0.0 §10.5.2.35 selects their layout using ACS in the containing SI4 message. Supply that bit as `runtime.SI4ACSZero` or `runtime.SI4ACSOne` to `DecodeSI7RestOctetsWithContext` / `DecodeSI8RestOctetsWithContext` and the matching `Encode…WithContext` function. `registry.DecodeWithContext` provides the same by printed name. ACS=1 selects `SI4RestOctetsO` plus `SI4RestOctetsS`; ACS=0 selects `SI4RestOctetsS` alone. A mismatched layout is rejected on encode.

`DecodeSI18RestOctets` implements the two stop conditions printed in TS 44.018 V19.0.0 §10.5.2.37h table 10.5.2.37h.1: a zero `NR_OF_CONTAINER_OCTETS` terminal record, or a fully used 20-octet SI message. Table 10.5.2.37h.2 assigns raw count code 31 to a container occupying all octets remaining in that SI value, including after an earlier container; codes 19–30 are reserved. Encode enforces that boundary. The `DecodeFrom` and `EncodeTo` forms measure the 20 octets from the current reader or writer position, leaving subsequent values untouched. The standalone `Non-GSM Message struct` decoder rejects code 31 because that count needs an enclosing SI value. `DecodeSI20RestOctets` uses the same grammar under §10.5.2.37i. Pycrate 0.7.11 accepts the literal fully used vector but rejects the printed zero-length terminal record; for `00 3f` plus 18 `aa` octets it instead reports an empty list and re-encodes `00 20`. Wireshark 4.6.8 reaches both SI message dissectors and exposes the exact rest-octet bytes, but no structural container fields. `DecodeSI19RestOctets` exposes the raw `NR_OF_REMAINING_CELLS` count 0–15, equal to the repeated-cell slice length, and interprets `FREQ_DIFF_LENGTH` as width 1–8. The printed grammar in §10.5.2.37g uses `* (val(NR_OF_REMAINING_CELLS))`; its "Range 1-16" prose conflicts with that repetition and with pycrate `si_19_rest_octets.py` and Wireshark `packet-gsm_rlcmac.c` COMPACT neighbour-cell repetitions. Pycrate 0.7.11 differs on a nonempty group vector. The source discrepancy is recorded in release-evidence.json.

`measurement.DecodeEnhancedMeasurementReport` enforces the five-bit message type `00100` from TS 44.018 V19.0.0 §10.4 table 10.4.2 and §9.1.55. Message type `00101` identifies Measurement Information and is rejected by both the EMR decoder and encoder.

`registry.Lookup(specification, printedName)` succeeds only when the name is unique in that specification. `registry.LookupClause(specification, clause, printedName)` resolves a clause-qualified definition. The canonical key is the specification number, clause and definition name exactly as printed. Each module contains exactly one version per standard, so `Version` stays descriptor metadata and is not a key component. Consumers track `main`, which moves to the current pinned version without carrying historical versions. For example, `A5 bits` occurs in two TS 24.008 clauses with different layouts, so an unqualified lookup returns both candidate clauses in an ambiguity error.

The same printed `PEO IMM Cell Group Details struct` appears in TS 44.018 §§10.5.2.16–18 and .25. Its Go type names receive a clause suffix such as `Clause105216`, while registry keys retain the printed name and exact clause. `restoctets.Lookup` rejects that unqualified name as ambiguous; `restoctets.LookupClause` resolves it.

The compiler turns a printed CSN.1 name into a Go identifier by joining runs of letters and digits, capitalizing each run, preserving existing uppercase runs, and prefixing `N` when the result begins with a digit. Anonymous optionals with one labeled value become pointers named after that value, such as `A5Bits *A5Bits`. An optional with several values becomes a pointer to a content-named `Group` struct. Multi-way choices use a content-named type and alternative fields named from labels unique to each branch; unlabeled branches use their bit pattern, such as `Alt01`. Repetitions contain element structs. Repeated labels in the same parent receive `Variant2`, `Variant3`, and so on; inserting a field with a different label does not rename existing public types. Repeated printed names across clauses receive deterministic clause suffixes in Go; an unresolved identifier collision stops generation.

## Arithmetic audit

`go test ./internal/arithaudit -count=1` scans production Go syntax for arithmetic and conversions involving decoder state. [arithmetic-allowlist.tsv](arithmetic-allowlist.tsv) classifies each file and expression with its expected occurrence count and the bound that makes it safe. The test fails when an expression appears, disappears, or changes count without review. Separate AST checks verify that every generated `uint8`, `uint16`, and `uint32` conversion from a decoded field fits its literal bit width and interpretation offset, and that every generated `uint64(v)` conversion has an unsigned source.
